# KV260 · Qwen3-1.7B 部署预算

**状态：软件模型与候选硬件参数；没有整机综合结果、时序收敛或 KV260 实测。** 本报告不证明完整 VPU/SPU/MMU 已实现。MB/GB 为十进制，MiB/GiB 为二进制。

复现（仓库根目录，Python + NumPy）：

```sh
python step3/kv260_report.py --context 1024 --lm-bits 4 --ddr-eff 0.8 --axi-eff 0.85 --axi-ports 4 --axi-bits 128 --axi-mhz 200 --mhz 200 --lanes 128 --page 8192 --fifo-pages 8 --spu-elems 4 --host-us 100 --reserved-mib 1024 --cycles --tokens 3
```

## 带宽与解码

有效带宽取两个独立瓶颈的较小值：`min(19.2 × DDR效率, HP端口数 × 位宽/8 × MHz/1000 × AXI效率)`。两个效率都是假设，既不是厂商保证，也不是软件 DDR memcpy 的测量值。端口仲裁、CPU/视频负载、突发长度和 outstanding 深度仍可能降低实际结果。

当前：DDR 侧上限 **15.360 GB/s**；AXI 原始上限 **12.800 GB/s**，AXI 效率 0.85；采用 **10.880 GB/s**。context=1024 指已有缓存 token 数，下一个 token 加入后为 1025。

| 每 token 项目 | 数量 |
|---|---|
| 整层 W4 权重 + scale | 726.663 MB |
| LM head 权重 + scale | 160.449 MB |
| KV 读取 / 写入（含 scale） | 59.638 / 0.058 MB |
| 总 DDR 流量 | 947.276 MB |
| MAC 数（1 MAC = 1 乘加） | 1.8380 G |
| 纯内存 / 纯 MAC 时间下界 | 87.066 / 71.797 ms |
| 理想重叠吞吐上界 | 11.486 tokens/s |
| 解析估算（含简化气泡/控制） | 11.472 tokens/s，未实测 |

字节数复用 `ddr_pager.token_traffic`；解析时间复用 `perf_model.token_time`，并强制不超过总字节带宽上界。模型假设 GQA 组内复用、计算/传输重叠、所有层和 LM head 均在加速器侧。当前 token 的 K/V 由片上路径提供，历史 KV 从 DDR 读取。未将 CPU 执行 SPU、逐算子主机往返等额外开销包含在内。

| 目标 | 必要有效带宽下限 | 必要 MAC 吞吐下限 |
|---|---|---|
| 8 tokens/s | 7.578 GB/s | 14.704 GMAC/s |
| 10 tokens/s | 9.473 GB/s | 18.380 GMAC/s |

这些只是必要条件；达到下限不保证目标速度。应先在目标镜像/驱动上测 PL 发起的实际页流量，再代入效率。

## 资源与内存可行性

当前单 token 所需镜像（包括容量为 1025 的 KV cache）为 **909.46 MiB**。预留系统/驱动/其它应用 1024 MiB（可改的预算假设），余下 3072 MiB；镜像后的余量为 2162.54 MiB。DDR 地址空间和 Linux 可用 DMA 分配区不是同一概念；必须实测 CMA/保留内存、物理地址映射和缓存一致性。

| 缓冲项目 | KiB |
|---|---|
| ISA scratch（当前编译器，FP32） | 129.00 |
| ISA 指令存储（128 bit/条，若驻片上） | 7.72 |
| MMU 权重页 FIFO（候选） | 64.00 |
| S 页双缓冲（候选） | 16.00 |
| VPU 激活 BFP16 乒乓暂存（候选） | 24.00 |
| GQA 注意力概率 FP32（候选） | 8.01 |
| RoPE 查找表（候选） | 8.00 |
| KV 写回暂存（候选） | 2.06 |

ISA scratch 与指令大小取自本次 `compile_decode` 输出；其它条目是仍待实现的内部缓冲预算。这里保留当前 FP32 scratch 的完整空间，没有用尚未实现的缓冲复用方案缩小预算。

片上缓冲有效载荷合计 **258.79 KiB**；BRAM+URAM 按常见 32/64-bit 数据宽度的总载荷容量为 2624 KiB。这是容量初筛，未计多端口复制、bank 划分、位宽/深度碎片、AXI/DMA/IP 和布线。BRAM 与 URAM 不能无条件互换。

DSP48E2 每片有一个 27×18 乘法器。按每路一个乘法器，128 路的乘法预算为 128 片（器件的 10.3%）；归约、scale、SPU 与控制仍要额外资源。P3 的 4×18×9 或 8×10×10 DSP 拆分不可直接套用到 DSP48E2；其 SIMD 加法并不等于独立小乘法器。[UG579](https://docs.amd.com/v/u/en-US/ug579-ultrascale-dsp)。本项目实际 LUT/FF/DSP/BRAM/URAM 占用及最高时钟均待 Vivado 报告。

8 KiB 是软件权重页，不是单个 AXI burst；MMU 必须按最大 burst 长度和 4 KiB 边界拆分。默认预填充路数与解码相同，不继承 P3 640/1280 路假设。此报告不预测批量预填充或整机功耗。

## 事件模型交叉检查

连续模拟 3 个 decode token，起始 context=1024，首个 token 为流水线预热；后续间隔平均 87.384 ms，核心吞吐 11.444 tokens/s；另加主机开销 100 µs 后为 11.431 tokens/s。

事件模型验证的是软件调度假设，不模拟真实 AXI 仲裁、RTL 握手或已实现电路；仿真一致不能作为上板速度证据。

## 部署验收

1. 用 KV260 board preset 生成 PS DDR/时钟/HP 接口配置，并记录工具、板文件、OS 和固件版本。[AMD Board Flow](https://docs.amd.com/r/en-US/ug1089-kv260-starter-kit/Vivado-Board-Flow)。
2. 测页读取、scale/KV 混合读写、1/2/4 HP 端口与空闲/应用负载下的持续带宽。
3. 逐个算子及整层与软件参考比对，再完成所有 28 层、Q/K Norm、LM head 和采样联调。
4. 真实 Qwen3 权重校验量化质量；分别测 TTFT 和不同上下文的持续 decode tokens/s，记录峰值内存及整板功耗。
